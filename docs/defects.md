# Реестр дефектов

## D-01: теряется дробная часть времени решения меньше миллисекунды

Приоритет: средний. Требование: F-08, разница closedAt-createdAt в среднем времени без необоснованного округления. Область: ReportService, Kotlin.

Шаги воспроизведения:

1. Через Java-интерфейс ReportSource передать в Kotlin-сервис одну RESOLVED-заявку с createdAt=2025-01-01T00:00:00Z и closedAt=2025-01-01T00:00:00.000500Z.
2. Запросить сводку по периоду, содержащему createdAt.
3. Проверить averageResolutionSeconds.

Ожидание: 0.0005 секунды. До исправления: 0.0, поскольку Duration.toMillis() отбрасывал долю миллисекунды до деления на 1000.0. PostgreSQL хранит микросекунды, поэтому дефект затрагивал и реальные записи.

Исправление: складывать целые секунды Duration.seconds и Duration.nano / 1_000_000_000.0; округление на уровне API не выполнять.

Регрессионный тест: ReportServiceTest.preservesSubMillisecondResolutionRegression. Он был выполнен до исправления и завершился AssertionFailedError; после исправления проходит вместе с полным набором. Сокращённый протокол до исправления сохранён в evidence/defect-D01-before.txt.

Статус: исправлен, проверен автоматическим тестом.
